# Защита от скачка ориентации

Гипотеза для сообщённого бага: при плохих landmarks или неудачных fit система может сменить ветвь ориентации, даже если рука остаётся видимой. Через 0.35s без успешного решения раньше выполнялась новая инициализация без памяти предыдущего наклона.

Теперь до 2s сохраняется прежняя ветвь как старт. Если новый fit меняет quaternion быстрее разрешённой огибающей, сохраняется предыдущая ориентация и положение повторно оценивается по anchors с фиксированным вращением. Неправдоподобное положение всё ещё отвергается по reprojection/cheirality. Геодезическая проверка не зависит от знака quaternion. Порог — 12 rad/s плюс 0.35 rad допуска; dt для проверки ограничен 0.1s, чтобы короткая потеря не разрешала произвольный полуповорот. Это консервативный предел, не измеренная скорость конкретного пользователя.

В логе hand quality добавлено orientation_held. При длительной потере (>2s) допускается новая инициализация; истинный быстрый поворот или неоднозначный ракурс может временно удерживаться либо отклоняться. Центровка не выполняется автоматически, сохранённых поправок нет, стороны по Vision.

Регрессионные тесты подставляют ошибочный 180-degree результат palm optimizer для обеих рук при обычном кадре и восстановлении после 0.4s. Проверяется сохранение quaternion при продолжающемся перемещении. Отдельно проверяется настоящий плавный поворот. Старый capture отсутствует по прежнему пути, реальная аппаратная проверка этого исправления пока не выполнена.
